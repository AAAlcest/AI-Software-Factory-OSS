# Contributing and reviewing

This distribution uses the [MIT License](LICENSE), selected by the Human owner.
Preserve applicable copyright and license notices. Submit only material you have
the right to contribute; no separate contributor agreement is introduced here.
Release preparation is not permission to change repository visibility.

Start at AGENTS.md and AI_ENTRYPOINT.md. Work from an explicit task and current
repository state. Use an Issue for bounded coordination and a PR for the exact
candidate, tests, findings and review. Ordinary product work does not need a
parallel mailbox/ACK cycle. Preserve meaningful review and defects; do not add
ceremony merely to reproduce a role chart.

For code or behavior changes, run `python -B scripts/check_all.py`; report actual
commands, interpreter/platform, failures and skips. For an expressly authorized
documentation/license-only change, inspect and check the changed files and their
direct links, preserving existing evidence instead of repeating the full process. Keep fixture data synthetic, network-free and deterministic.
New scripts must describe their effects, reject ambiguous targets and never
infer authority from a title, credential or a structurally valid declaration.

An author check, independent technical review, final privacy review, fresh-Agent
run, license decision and publication authorization are different facts. Never
claim one because another succeeded. Do not commit real operating histories,
secrets, private endpoints, customer data or identifying logs. Preserve finalized
historical handoffs; put corrections in current state or a later record.

The final reviewer considers the integrated candidate, not merely a sum of old
slice approvals. Keep reports on the relevant Issue/PR and do not alter a pinned
acceptance target without recording the new identity and affected revalidation.
