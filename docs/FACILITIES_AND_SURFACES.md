# Facilities and Surfaces

## Staff Office

Durable home for one organizational role: onboarding, inbox/outbox, current desk state, pending work and role-local continuity records.

## Project Room

Durable operational twin for a software project. It stores project identity, state, authority pointers, blockers, decisions and evidence references without copying the product repository source tree.

## Project Mailbox

A project may be a first-class correspondence endpoint with its own `inbox/` and `outbox/`. The current Project Primary operates that mailbox; the mailbox belongs to the project, not to one chat.

## Meeting Hall

GitHub Issues can be specialized as Meeting / Coordination Surfaces for deliberation, cross-role review, architecture discussion, Human decision points and long-running open loops.

## Development Portfolio Console

A portfolio visibility/control-tower surface. It sees material project correspondence and project state, detects stalls and missing evidence, but does not gain project execution authority merely by visibility.

## Evidence and State

Factory State and Project State summarize current truth. Evidence proves implementation, testing, review or integration facts. Historical records inform provenance but do not silently override current state.

## Office Wardrobe

Optional recommended facility for recording transitions from an office role into Work/Codex/agent execution sessions and back.

## Handoff Archive

Finalized tenure handoffs are append-only historical records used for true succession.
