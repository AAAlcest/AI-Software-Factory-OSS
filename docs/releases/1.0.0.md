# AI Software Factory OSS 1.0.0

Release tag: `v1.0.0`.

## Included

Repository-first role, authority and state guidance; recommended ChatGPT management
and Codex engineering roles with limited Work use; Staff Office and Project Room
surfaces; Issue/PR coordination; optional one-body correspondence and mandatory CC
routing; Development Portfolio Console visibility; Work Invocation History; and
first-appointment, recovery and authorized-succession exercises.

The repository includes both deterministic generated synthetic Factory packages and
a checked-in, browseable [synthetic Factory instance](../../examples/factory-instance/README.md)
so readers can inspect Office, Project Room, Factory state, registers and mailbox
shapes directly in GitHub before generating a disposable fixture.

The public README is available in English and Simplified Chinese. FlowThread is shown
as a real Quirmn product incubated through this Factory workflow; it is an example,
not a dependency or required purchase.

The distribution is licensed under [MIT](../../LICENSE).

## Acceptance evidence retained

profiles, root Agent entrypoints and workflow definitions remain unchanged.

The final release delta is checked proportionately rather than rerunning the full
accepted behavioral/fresh-Agent matrix for documentation-only additions.

## Security and known limits

This repository uses GitHub Private Vulnerability Reporting and does not publish a
personal email address for vulnerability reports. See [SECURITY.md](../../SECURITY.md).
Do not publish vulnerability details in public Issues or PRs.

The helpers validate declarations, not real organizational authority, evidence
authenticity or live security boundaries. Fresh-Agent observation on a shared host
is not proof of an OS-enforced sandbox. No automatic agent scheduling,
authenticated delivery, production deployment, external-system access or security
guarantee is provided.

## Release integrity

`v1.0.0` must point to the exact final release commit and must not be moved after
publication. The GitHub Release should use these notes and should not attach private
logs, credentials or unrelated assets. Publication evidence and final readback are
recorded in Issue #1.
