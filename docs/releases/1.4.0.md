# AI Software Factory OSS 1.4.0

Release tag: `v1.4.0`.

Version 1.4.0 is a cumulative operating release over the original `v1.0.0`
public baseline. It keeps repository evidence authoritative while adding bounded
management, recovery, visibility and audit layers for longer-lived AI software
work.

## What changed since 1.0.0

### Project cockpit and bounded context

The V1.1 layer adds an optional ChatGPT Project cockpit for Factory/project/role
overview, recovery, handoff support, health inspection and bounded Codex task
packaging. The cockpit is explicitly derived context: repository state and evidence
remain canonical.

Eight reusable skill contracts cover Factory/project/role overview, recovery,
handoff, health and task packaging. The token-efficiency design measures observable
files/bytes and exposed token counts where available without promising a fixed
saving percentage.

### Executable cockpit generation and drift detection

The V1.2 layer adds executable cockpit generation, source fingerprints and drift
checking, plus composable skill adapters and context measurement. Recovery mode is
derived from repository continuity evidence rather than selected by the caller.
Generated bundles fail closed when stale or invalid and do not authorize execution.

### Work-item checkpoints and long-thread recovery

The V1.3 layer adds one Project-visible work item per workstream, bounded current
checkpoints, superseded references, last-evidence pointers, Human gates and next
safe actions. `generate_project_view.py` exports Markdown/JSON/CSV management views
without mutating GitHub Project state.

The intended recovery path is:

`Work Item -> Current Checkpoint -> Current Surface / Evidence -> Next Action`

Older chronology is expanded only when a concrete dependency, conflict or missing
fact remains. A real fresh-context acceptance against V1.3 recovered the selected
synthetic lane without replaying the target Issue chronology and recorded `PASS` in
Issue #15.

### Fresh Factory Audit and governance-drift diagnostics

The V1.4 layer adds a reusable fresh-context Factory audit pattern, a generic audit
Issue template, a generic Fresh Auditor prompt and newly authored synthetic stress
cases. The examples cover failure modes such as missing central project visibility,
frozen work resurfacing as active, superseded direction lingering in a roll-up,
stale release/visibility propagation, stale recovery queues and orphaned draft PRs.

Audit findings are evidence for later Human/management disposition. They do not
authorize remediation, merge, release, publication, deployment, credential use or
production changes.

## Public/private boundary

All checked-in Factory instances, checkpoints, audit findings and examples in this
repository are synthetic public material. Real private Factory histories, private
Issue chronology, appointments, company/customer facts, credentials and production
evidence must not be copied or merely renamed into public examples.

The public OSS framework can be used as a reference model; an operator's own
repository remains the authority for its organization and projects.

## Security and limits

The repository uses GitHub Private Vulnerability Reporting and does not publish a
personal vulnerability-reporting email. See [SECURITY.md](../../SECURITY.md).

The helpers validate declared repository relationships and derived bundles. They do
not prove real organizational authority, evidence authenticity, OS isolation,
production security, or external-system permission. The project does not provide
autonomous scheduling, authenticated mail transport, production deployment, secret
management or automatic private/public synchronization.
