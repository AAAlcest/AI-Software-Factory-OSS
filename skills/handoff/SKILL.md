# Skill: handoff

Purpose: classify the continuity event and prepare the correct handoff/recovery material.

Inputs: role/project, current incumbent, proposed/new incumbent when applicable, explicit Human authorization evidence when succession is claimed.

Modes:

- `FIRST_APPOINTMENT`: no predecessor handoff.
- `SAME_INCUMBENT_RECOVERY`: preserve tenure; refresh current state; no immutable handoff.
- `TRUE_SUCCESSION`: requires an explicitly authorized incumbent change; finalized predecessor handoff becomes immutable history.

Output: classified mode, authority evidence, recovery/handoff brief, unresolved facts and next safe action.

Never upgrade a chat/model/device change into succession.
