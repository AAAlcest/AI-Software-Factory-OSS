and Codex engineering roles with limited Work use; Office/Project Room templates;
Issue/PR coordination; optional one-body correspondence and mandatory CC routing;

packages; and first-appointment, recovery and authorized-succession exercises.

## Security and known limits

The selected confidential reporting route is GitHub Private Vulnerability
Reporting; no personal email is published. Channel enablement and the private
form entry must be verified as part of the authorized Public rollout, before
publishing the Release. See [SECURITY.md](../../SECURITY.md).

The helpers validate declarations, not real authority, evidence authenticity or
live security boundaries. Fresh-Agent observation on a shared host is not proof
of an OS-enforced sandbox. No automatic agent scheduling, authenticated delivery,
production deployment, external-system access or security guarantee is provided.

## Publication gate

Await explicit Human approval of the final SHA, Public visibility and Release
publication. Follow the [rollout checklist](../PUBLICATION_CHECKLIST.md), including
the bounded license/security/docs privacy delta and reporting entry verification.
Do not attach private logs, credentials or unrelated assets. Once authorized,
publish from the approved commit without silently substituting a newer `main`.
