# Skill: task-packaging

Purpose: package a bounded implementation request for Codex so engineering can begin without rereading the whole Factory by default.

Inputs: selected project/task plus a fresh project overview and applicable Human/management decisions.

Output must include: exact task, target repository/project, relevant paths, current ref/SHA when material, accepted decisions, constraints/Human gates, expected outputs, required checks/evidence and source pointers.

Expansion rule: Codex may read beyond the package only for a concrete implementation dependency, conflict or missing fact discovered during work.

Do not omit required safety/authority facts merely to save tokens. Context efficiency is subordinate to correctness.
