# Security and disclosure boundaries

The helpers are offline declaration/fixture tools, not authorization services,
transport security or sandboxes against concurrent filesystem mutation. Never
run an unknown repository script against production or confidential material
merely because it is named a validator. Use disposable synthetic inputs first.

Do not post credentials, private hostnames, customer facts or exploit evidence
containing sensitive material into an Issue/PR intended for future publication.
Use an explicitly authorized private disclosure channel for such evidence.
A public security-contact address has not yet been configured; do not invent one
or treat a public issue as a safe secret-reporting channel. Configuring a channel
before publication is part of the Human publication readiness decision.

Describe public-safe reproduction steps with synthetic data, exact candidate and
actual observed impact. A clean keyword scan is not semantic privacy clearance.
Final independent privacy/public-safety review and explicit Human publication
approval remain required; this document grants neither.
