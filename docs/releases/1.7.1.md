and the [packaging receipt in PR #59](https://github.com/AAAlcest/AI-Software-Factory-OSS/pull/59)

## Changes since v1.7.0

This patch includes both [#58](https://github.com/AAAlcest/AI-Software-Factory-OSS/pull/58)
and [#59](https://github.com/AAAlcest/AI-Software-Factory-OSS/pull/59), plus version
and current-use documentation reconciliation. It is not only three Markdown edits.

- **Teach the working split during creation.** The public Agent entrypoints and
  [role guide](../RECOMMENDED_ROLE_SETUP.md) explain why an ordinary chat manager
  works with the Human on intent, design, trade-offs, task scope and acceptance,
  while an engineering Agent with actual files, editing, terminal and test tools
  implements the agreed work. The manager inspects delivery evidence and decides
  the next authorized step; it is not just a message relay.
- **Put the recommendation in the bootstrap preview.** The existing read-only
  private-bootstrap command now points to the role guide and asks the Human to
  choose appropriate tools and responsibilities before applying. It remains
  noninteractive and does not create sessions, appointments or remote state in
  preview mode.
- **Carry the guide into new private starters.** Bootstrap copies
  `docs/RECOMMENDED_ROLE_SETUP.md` and references it from the generated README and
  entrypoint. The copied guide includes the corrected chat-management rationale.
  New instances still start BLOCKED/UNCONFIGURED, with unknown authority and an
  inactive documentation-journal writer.
- **Keep current release instructions consistent.** `VERSION`, bilingual landing
  pages, Quickstarts, Quick Demo, private-upgrade instructions and the docs/status
  indexes now distinguish the 1.7.1 source candidate from published historical
  releases. Existing release notes and tags are preserved.

Management can use authorized GitHub connectors. Provider choices remain optional;
capabilities and authority determine suitable roles. Avoiding coding runs for
ordinary management discussion is the intended efficiency mechanism, not a
promise of free/unlimited chat, separately metered plans or fixed savings.

## Use and compatibility

After verifying that `v1.7.1` is published at the approved commit:

```sh
git clone https://github.com/AAAlcest/AI-Software-Factory-OSS.git
cd AI-Software-Factory-OSS
git checkout --detach v1.7.1
```

Follow the [Quickstart](../QUICKSTART.md) or
[Chinese Quickstart](../QUICKSTART_ZH.md). Before publication, use an actually
published release for stable use; do not assume the proposed tag exists.

Bootstrap and upgrade derive their accepted release tag from `VERSION` and retain
exact official-source identity checks. Tag mode requires a lightweight commit tag
with matching local/origin/GitHub API targets; clean exact official `main` remains
supported. Python 3.10+, Git and authenticated GitHub CLI requirements are unchanged.
No real private repository is created or modified merely by reading these notes.

For **existing** private Factories, the [minimal updater](../PRIVATE_FACTORY_UPGRADE.md)
still manages only `scripts/validate_instance.py`,
`templates/STAFF_OFFICE_TEMPLATE.md` and `templates/PROJECT_ROOM_TEMPLATE.md`.
It does **not** install this new onboarding guide or replace a private entrypoint.
Do not advertise the three-file update as a whole-Factory migration. The updater
still defaults to read-only preview; explicitly authorized apply prepares a private
Draft PR, without pushing private main or auto-merging.

Journal cadence, opt-in/activation gates, existing private data and authority,
credentials, historical releases and website deployment are unchanged. This patch
adds no role picker, automatic Agent dispatch, new execution system or PDF feature.
